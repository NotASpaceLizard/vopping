# Backlog

**Scope (per PO, 2026-09-04):** single-user, fully offline, self-contained webapp — used almost
exclusively on a phone, in a grocery store. This supersedes the stale top-of-file framing in
`project-notes.md`, which was written when this was conceived as a multi-user app requiring a
backend (a hard blocker at the time). That requirement is now moot: every multi-user-editing and
shareable-link requirement from `project-notes.md` has been dropped entirely, not deferred. Every
other requirement in that file's Requirements section is intact below as a real story.

**Tech stack decision (locked, 2026-09-04):** plain HTML/CSS/JS, no framework, no build step, no
backend, persistence via `localStorage` — identical architecture to sibling project vacking
(confirmed via vacking's own BACKLOG.md tech-stack decision note). Works entirely via `file://` or
a static host; no network calls of any kind are part of this app's normal operation.

**Row density/interaction — LOCKED, 2026-09-04 (PO's final pick from `density-picker.html`):** vacking's row density (44px
checkboxes, no row-to-row margin, ~52px/row) was too sparse for grocery use in practice — excessive
scrolling, real risk of missing an item while scanning aisles mid-shop. The Orchestrator has built
`density-picker.html` in this project's root: a real interactive side-by-side comparison of 4 row-
density options. **PO's final pick:** the entire row is the tap target for toggling crossed-off
state (Option C), with no checkbox or dot glyph of any kind (Option D) — since the whole row
already toggles on tap, a dedicated glyph isn't needed for the everyday cross-off gesture;
crossed-off visual state is strikethrough + dimmed item-name text only. This is now the real spec
for S1's base row, S2's tap/cross-off behavior, and S5's up/down buttons — see each story's own row
for the full locked detail. Exact CSS/markup still needs a Developer pass and Tester
re-verification before Status can move to Done on any of the three; see the Tracked follow-up note
below.
