S26 — Aisle presentation + aisle icon

S26 moves the per-item aisle off its always-present second-line <select> (which currently forces EVERY row to two lines, even aisle-less ones) onto an icon in line with the other per-row icons. Two things need your eye. Rows below use the REAL current row markup/CSS (the post-S14/S20 frameless 19.5px icons), rendered at true on-device widths.

The core fix is fixed, not a choice: an item with NO aisle set stays a SINGLE line either way (see the Bread row). What you're picking is only how an item that HAS an aisle set should show it.

(a) Set-aisle presentation — pick ONE

Same 5-item list in both options. Note vs. aisle: a set NOTE always shows on the second line (that's unchanged from today). The only thing that differs between the two options is where a set AISLE goes.

Option 1 — Tag when set (aisle icon stays on the primary line; the value drops to a compact second-line tag only when set)

Roomy, uncluttered primary line; a set aisle costs a second line (like a set note already does). Aisle-less rows stay single-line.

Option 2 — Inline (the value shows on the primary line; the collapsed control widens to show it)

A set aisle stays on ONE line (no second row) — but the value competes with the item name for width, so long names truncate sooner, especially at 320px.

(b) Aisle icon glyph — pick ONE (or send your own codepoint)

Plain monochrome Unicode symbols only, no colored emoji (your standing preference). Each is rendered as a real character via String.fromCodePoint() at the actual 19.5px footprint, sitting in a full real row beside the other icons (note , edit, up, down, delete) so you can judge weight/consistency in context. U+2691 (⚑) is S16's prior aisle flag.

Each carries an automated tofu check: the glyph is drawn to an offscreen canvas and compared pixel-for-pixel against a guaranteed-unassigned codepoint. A match flags a likely missing-glyph box in this test browser — worth double-checking directly on your phone, since obscure codepoints are font-dependent.
